更新日期：2026-11-12。依据本次生产上线核验和当前代码整理；下面的未完成项没有因为写入本文而自动启用。

当前已上线预测、研究池、后台调度、到期结算、复盘与经验试验流程，六个服务正常运行，9 个 Profile 通过真实调用与恢复验证。Alpaca 行情和新闻已接入，飞书连接及单条通知投递已验证。详见[上线记录](implementation-status.md#预测与研究沉淀版本生产上线2026-11-12)。

最先要补的是四个数据源配置，然后确认个人持仓和研究预算。股东大会音视频、动态评论、专业分析师筛选等还需要开发；预测准确率和经验效果则需要真实运行积累。

## 1. 已有适配器，等待配置与真实验收

下表优先级是本项目的实施顺序建议。生产 Web、Worker、Tools 进程均已核实缺少这四项配置。

| 优先级 | 来源 | 需要提供 | 当前代码接入范围 | 配置后必须验证 |
| --- | --- | --- | --- | --- |
| P1 | SEC 公司披露 | `SEC_USER_AGENT`，填写应用名称和真实联系邮箱，例如 `Youwei Research contact@example.com`；示例邮箱需要替换。这不是 API Key | 公司档案、近期申报、部分申报正文、部分 XBRL 财务指标；覆盖代码筛选到的 10-K、10-Q、8-K、20-F、6-K、DEF 14A、Form 4、13F-HR 等记录 | 股票到 CIK 的映射、申报日期及来源链接正确；正文和财务数据实际可取，失败或截断明确标记 |
| P1 | 网页搜索 | `BRAVE_SEARCH_API_KEY` | 搜索股票、财报、投资者关系、展望和讨论页面，再提取公开 HTML 文本 | 搜索返回真实结果，原文能读取，保存 URL、采集时间及证据引用 |
| P1 | 宏观环境 | `FRED_API_KEY` | DFF、DGS10、T10Y2Y、CPIAUCSL、UNRATE、VIXCLS 六个序列，即利率、收益率曲线、通胀、失业率和波动率相关数据 | 六个序列逐项核验；保存观测日期与所请求的数据版本日期；缺失序列不能当成零值 |
| P2 | X 讨论 | `X_BEARER_TOKEN`，对应账号需要能调用当前代码使用的近期搜索接口 | 按股票代码搜索英文讨论，记录作者、正文、会话引用及采集时的互动指标 | 真实请求可用，作者和时间可追溯；配额、权限、空结果和截断能区分 |

这些适配器已经实现，但尚未完成上述生产数据源的真实接通验收。填入环境变量只代表配置存在，不代表请求成功。

当前实现边界：

- 未配置 Brave 时，采集工具仍支持显式提供公开网页 URL；不会自动获得搜索结果。
- 网页适配器只提取公开 HTML，不执行页面 JavaScript，不包含动态评论加载、登录后内容或音视频转写。
- X 当前使用近期搜索，代码将起始时间限制在最近约六天，单次最多取 50 条；不是历史全量搜索，也没有专业作者筛选。
- SEC 当前从目标公司的近期申报列表取资料，最多选 12 条，只尝试读取其中部分正文。并不等于完整的机构 13F 持仓汇总；财务事实保留 `pointInTimeVerified=false`，不能宣称已完成严格的历史时点重建。
- Alpaca 新闻当前单次最多 50 条，存在后续分页时会标记截断；既有行情使用的 feed 覆盖范围随数据保留，不能把 IEX 当作全市场成交数据。

## 2. 配置如何进入生产

建议由运维创建独立私有环境文件 `/opt/hermes-alpha-lab/private/research-sources.env`。这是待执行方案，当前尚未创建或挂载该文件。

```dotenv
SEC_USER_AGENT="Youwei Research <替换为真实联系邮箱>"
BRAVE_SEARCH_API_KEY=<待提供>
FRED_API_KEY=<待提供>
X_BEARER_TOKEN=<待提供>
```

执行步骤：

1. 用户准备真实联系邮箱和三个服务的可用凭证；缺少的项先省略，不把占位符写入生产。
2. 在服务器私有目录保存配置，以 systemd `EnvironmentFile` 方式加载到 Web、Worker、Tools。Worker 和 Tools 执行采集，Web 展示来源可用状态；三者保持一致。文档不记录凭证值。
3. 核对活跃任务，按既有部署流程加载新配置并重启相关服务；不重复初始化数据库或 Profile。
4. 分别对一只实际关注的股票调用每个来源，检查采集结果、证据正文、时间、引用及失败原因。宏观来源逐个检查六个序列。
5. 再做一次组合采集和研究，确认总采集预算下仍能取得有效资料。当前总采集预算约 22 秒，多来源启用后可能出现部分完成，必须保留真实状态。
6. 在本文更新接通日期、实际结果和证据位置，再标记完成。

本阶段验收清单：

- [ ] SEC：配置就绪，真实申报与财务数据采集完成。
- [ ] Brave：配置就绪，搜索与原文采集完成。
- [ ] FRED：配置就绪，六个序列逐项验收。
- [ ] X：配置就绪，近期搜索真实可用。
- [ ] Web、Worker、Tools 来源状态一致，组合采集可用。

## 3. 用户需要确认的研究设置

这些设置已经有实现，需要填入实际偏好，不属于重新开发。

| 项目 | 当前行为或默认值 | 待确认内容 |
| --- | --- | --- |
| 持仓 | 从用户最新组合快照的正数量持仓同步研究池 | 核对股票、数量及持仓快照是否为当前实际持仓 |
| 自选股 | 用户主动关注的股票进入持续研究池 | 添加长期关注股票，暂停不再跟踪的标的 |
| 临时提问 | 支持临时研究池，按交易日设置到期时间 | 验证实际提问的股票进入临时池；需要长期跟踪时改为关注 |
| 每日研究数量 | 默认 `dailyResearchLimit=30` | 根据期望研究量和实际模型调用耗时调整 |
| 每日新候选数量 | 默认 `dailyCandidateLimit=10`，不得超过每日研究数量 | 优先聚焦持仓时可减少，设为 0 可停止增加候选 |
| 后台研究 | 默认 `enabled=true` | 确认是否持续自动研究 |
| 飞书通知 | 默认 `feishuNotifications=true` | 确认通知偏好，并在真实业务触发时验证去重与投递结果 |

上述每日数量是标的数量预算，不是金额或 token 预算；金额/token 成本上限需要另外设计。既有单条飞书测试已完成，不需要重复发送测试通知来补齐配置。

## 5. 需要真实运行积累的验证

这部分已有流程与测试，但仍缺长期生产效果证据。

- [ ] 第一批生产 5 个交易日预测到期后，检查实际结算、相对 SPY 收益、误差指标及复盘记录。
- [ ] 第一批生产 20 个交易日预测到期后，完成同样的验证。到期日以各预测记录为准，不使用隔离验收库的日期代替。
- [ ] 验证行情缺失时保持待补数据，不提前结算或填造收益。
- [ ] 同时复盘预测成功和失败案例，核对原始预测、当时证据和事后结果均可追溯。
- [ ] 经验候选用独立的对照/候选会话验证。当前晋升评估至少需要 30 个新事件样本；通用经验还要求至少覆盖 5 家公司。达到数量只是评估门槛，不保证晋升。
- [ ] 观察采用经验后的效果，以及效果恶化时的降级；不能把模型写出一段“经验总结”当作已经学会。
- [ ] 按预测期限、公司、事件类型和置信度累计评估，记录样本量；不能用少量命中宣称预测能力提升。
